### AC-1: Stop hook이 세션의 단계별 시간 신호를 로컬에 기록한다
Given 피드백 수집이 켜진 하네스에서 테스트 실행, 리뷰, hook 차단이 한 번 이상 일어난 세션이 있다
When 그 세션이 끝나 Stop hook이 실행된다
Then 로컬 저장소에 그 세션의 기록이 새로 하나 생기고, 기록에는 테스트 대기 시간, 리뷰 횟수, 같은 변경의 반복 리뷰 횟수, hook 차단 횟수, timeout 횟수가 들어 있다

### AC-2: 수집에는 모델 호출이 없고 비용이 0이다
Given 피드백 수집이 켜져 있다
When 세션이 끝나 Stop hook이 기록을 남긴다
Then 그 세션의 비용/사용량 기록에 수집 때문에 생긴 모델 호출은 0건이고 추가 비용은 0이다

### AC-3: 수집은 하네스 동작을 바꾸지 않는다
Given 같은 작업을 피드백 수집을 켠 상태와 끈 상태에서 각각 실행한다
When 두 세션이 끝난다
Then 두 세션의 테스트 결과, 리뷰 결과, hook 차단 여부, 종료 코드가 같고, 수집 때문에 차단되거나 실패한 단계가 없다

### AC-4: 기록 실패가 세션을 막지 않는다
Given 로컬 기록 위치에 쓸 수 없는 상태다
When 세션이 끝나 Stop hook이 실행된다
Then 세션은 수집을 켜지 않았을 때와 같은 종료 코드로 정상 종료되고, 그 세션의 기록은 생기지 않는다

### AC-5: `auto` 보고서가 여러 세션에서 반복된 낭비 패턴을 보여 준다
Given 로컬 기록에 테스트 대기와 같은 변경의 두 번째 리뷰가 시간의 큰 비중을 차지한 세션이 3개 이상 있다
When 사용자가 `auto` 보고서를 연다
Then 보고서에 해당 패턴이 패턴 종류, 해당 세션 수, 세션별 시간 비중(예: 테스트 대기 %, 반복 리뷰 %)과 함께 나온다

### AC-6: 한 세션에서만 나온 신호는 반복 패턴으로 보고하지 않는다
Given 어떤 낭비 신호가 반복 기준(세션 3개)보다 적은 세션에서만 기록되어 있다
When 사용자가 `auto` 보고서를 연다
Then 보고서의 반복 패턴 목록에 그 신호가 나오지 않는다

### AC-7: 기록이 없으면 보고서가 그렇다고 알린다
Given 로컬 기록에 세션이 하나도 없다
When 사용자가 `auto` 보고서를 연다
Then 보고서는 성공적으로 끝나고, 분석할 세션 기록이 없다는 문구를 보여 주며, 반복 패턴은 하나도 나오지 않는다

### AC-8: 사용자가 요청하면 반복 패턴이 규칙/hook 수정 후보가 된다
Given `auto` 보고서에 반복 패턴이 하나 이상 있다
When 사용자가 그 패턴으로 후보 작성을 요청한다
Then 근거 패턴과 근거 세션 수, 바꿀 규칙 또는 hook의 수정안이 담긴 후보가 생기고, 후보 상태는 "반증 대기"이며, 이번 후보 작성에 쓴 모델 비용이 표시된다

### AC-9: 후보는 다른 제공자의 반증을 거쳐야 사람 승인 단계로 넘어간다
Given "반증 대기" 상태의 후보가 있다
When 승인 흐름이 실행된다
Then 후보 작성에 쓰지 않은 다른 제공자가 반증한 결과(제공자 이름과 판단 근거)가 후보에 붙고, 그 다음에야 후보가 사람 승인 목록에 나온다

### AC-10: 반증된 후보는 사람 승인 목록에 오르지 않는다
Given 다른 제공자가 반증에서 후보를 기각했다
When 사용자가 사람 승인 목록을 연다
Then 그 후보는 목록에 없고, 기각 상태와 기각 사유로 따로 확인할 수 있다

### AC-11: 다른 제공자를 쓸 수 없으면 후보는 대기 상태로 남는다
Given 후보 작성과 다른 제공자를 쓸 수 없는 상태다
When 승인 흐름이 실행된다
Then 후보는 "반증 대기" 상태로 남고, 사람 승인 목록에 나오지 않으며, 반증 제공자를 쓸 수 없다는 메시지가 나온다

### AC-12: 사람이 승인하기 전에는 규칙/hook이 바뀌지 않는다
Given 반증을 통과해 사람 승인 목록에 오른 후보가 있다
When 사람이 아직 승인하지 않았거나 거절한다
Then 하네스의 규칙 파일과 hook 파일 내용은 후보가 생기기 전과 똑같고, 거절한 후보는 "거절" 상태로 기록된다

### AC-13: 사람이 승인하면 후보가 승인된 수정안으로 기록된다
Given 반증을 통과해 사람 승인 목록에 오른 후보가 있다
When 사람이 후보를 승인한다
Then 후보 상태가 "승인"으로 바뀌고, 승인된 규칙/hook 수정안을 볼 수 있으며, 규칙/hook 파일은 자동으로 바뀌지 않는다

### AC-14: 벤치마크 자동 검증은 돌지 않는다
Given 후보를 작성하고, 반증하고, 승인하는 전체 흐름이 끝났다
When 사용자가 그 흐름의 실행 기록을 확인한다
Then 벤치마크 실행이나 벤치마크 기반 검증 단계가 기록에 없다
