사용자 요청: "하네스가 자체적으로 진화할 수 이는 피드백 시스템이 갖춰지면 좋을것 같긴한데.."

범위 질문에 사용자가 고른 답: "제안·승인까지"
- 수집: Stop hook이 실제 세션의 단계별 시간(테스트 대기, 리뷰 횟수, 같은 변경의 반복 리뷰, hook 차단, timeout)을 로컬에 쌓는다. 모델 비용 0, 하네스 동작은 바꾸지 않는다.
- 탐지: 여러 세션에서 반복되는 낭비 패턴을 `auto` 보고서로 보여 준다.
- 제안·승인: 반복 신호를 규칙/hook 수정 후보로 만들어 checklist와 같은 승인 흐름(다른 제공자 반증 → 사람 승인)에 올린다. 후보 작성에 모델 호출이 들어가 회당 소액 비용이 든다.
- 벤치마크 자동 검증은 이번 범위가 아니다.

배경: 품질 쪽 순환(auto checklist: 놓친 결함 → 점검 후보 → 반증 → 승인)은 이미 있다. 이번 세션에서는 Pilot C 벤치마크로 시간이 테스트 대기(56–64%)와 같은 변경의 두 번째 리뷰(41–58%)에 쓰인다는 것을 사람과 에이전트가 손으로 분석해 고쳤다. 하네스가 이 분석을 스스로 하게 하려는 것이다.
