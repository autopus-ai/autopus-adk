7. Defect found and fixed (flagged: production change 608cfcde)
----------------------------------------------------------------
symptom: concurrent `auto fix lock` on a store that does not exist yet: some
  processes exit 1 with "lock state is unusable:
  .autopus/runtime/fix-locks/.store.lock" (7 of 30 rounds of 8 processes, 13
  of 240 processes). Violates S17 step 4 and REQ-EG-06. The pkg test locked
  once before its concurrent lockers, so the lock file always pre-existed.
loop: scratch script, K processes per fresh store, red rounds counted; with
  the store lock file pre-created, 0 of 30 rounds were red.
root cause: openStoreLock opens the lock file with os.Root OpenFile
  (openat O_RDWR|O_CREAT|O_NOFOLLOW). On darwin that open can fail with
  ENOENT when another creator makes the same name at the same moment.
  Differential probe, 8 concurrent creators x 60 rounds per mode: os.Root
  OpenFile 4/480 failures (9/480 when the racers also create the directory);
  absolute-path os.OpenFile 0/480 with and without O_NOFOLLOW. At the failure
  the directory fd was the live directory at that path (13/13 same inode).
  Rejected hypotheses: directory removed or replaced; Mkdir/OpenRoot race;
  flock error.
fix: retry the same open on ENOENT, at most 3 attempts; by then the name
  exists, so the open no longer creates. The regular-file and SameFile checks
  after the open are unchanged.
after: 0/320 (8 x 40 rounds) and 0/480 (16 x 30 rounds) failed processes.
same pattern elsewhere (not changed, outside this SPEC): pkg/rulecond
  sticky_state.go opens its counter with os.Root OpenFile(O_RDWR|O_CREATE);
  there a failure is the silent "unusable state" path of STICKYRULE.
