사용자 요청 (대화 원문 요약 포함):
"응 차라리 그하네스가 그구조를 잡아주는 형태로 하면되잖아 에이전트가 코드베이스를 읽을거고."

맥락: auto harness(세션 낭비를 규칙 후보로 만들고, 다른 provider가 반증하고, 사람이 승인하면 .claude/rules/harness-lessons.md에 글 규칙을 쓰는 기능)는 지금 승인된 교훈을 글로만 남긴다. 사용자는 강연("All Code Is Slop", 신뢰 피라미드: API로 없애기 > lint/타입 > 테스트 > hook > 글)을 보고, 하네스가 교훈을 저장소의 검사로 바꾸는 구조를 잡아 주고, 실제 구현은 코드베이스를 읽는 작업 에이전트가 하도록 하자고 했다. 교훈 출처는 세션 낭비에 더해 반복되는 리뷰 지적까지 넣기로 했다(이번 요청의 첫 단계는 승인된 교훈을 검사로 바꾸는 단계이고, 리뷰 지적 출처는 다음 단계다).

첫 단계에 기대하는 동작:
- 교훈을 승인하면 작업 에이전트가 받을 구조화 지시(가장 강한 층을 고르는 순서, 실수를 재현하는 patch, 검사 명령)가 나온다.
- 에이전트가 검사를 만들면 하네스가 직접 증명한다: 재현 patch를 적용한 트리에서 검사가 실패하고, 지금 트리에서는 통과해야 한다. 하네스가 실행하지 않은 자기 보고는 받지 않는다.
- 증명된 교훈은 글 규칙 파일에서 빠지고 상태에 검사 명령과 층이 남는다. 구조화가 불가능하면 이유와 함께 글 규칙으로 남길 수 있다.
- 증명 전까지 글 규칙은 임시로 유지된다.
