사용자 요청: "응 차라리 그하네스가 그구조를 잡아주는 형태로 하면되잖아 에이전트가 코드베이스를 읽을거고." 그리고 교훈 출처 질문에 "리뷰 지적까지 (Recommended)"를 골랐다.

맥락: auto harness는 Claude Code Stop hook이 세션 기록(transcript)을 모델 호출 없이 읽어 시간 낭비 패턴(테스트 대기, 리뷰 비중, 반복 리뷰, Stop 차단, timeout)을 세고, 세션 3개 이상에서 반복되면 provider 하나가 규칙 초안을 쓰고 다른 provider가 반증한 뒤 사람이 승인한다. 승인한 교훈은 auto harness encode로 저장소 검사로 바꾼다(이미 구현됨).

이번 요청: 반복되는 리뷰 지적도 교훈 출처가 되게 한다. lint 규칙으로 바뀌는 실수는 보통 리뷰가 반복해서 잡는 실수이기 때문이다.
기대 동작:
- 세션 기록에서 리뷰어의 보고서(동기 리뷰 결과, 백그라운드 리뷰어가 나중에 보내는 메시지 모두)를 읽어 file:line을 가리키는 지적을 모은다. 모델을 부르지 않는다. 프로젝트 밖 경로, 코드 블록 안의 재현 명령, 재리뷰의 상태 표는 지적으로 세지 않는다. 리뷰어가 아닌 에이전트의 메시지는 읽지 않는다.
- 같은 코드 영역(경로의 앞 두 단계)에서 세션 3개 이상에 지적이 나오면 반복 패턴이 되고, auto harness report가 세션마다 예시 지적을 보여 준다.
- 그 패턴의 초안은 지적들이 하나의 같은 실수(lint·타입 검사·테스트가 잡을 수 있는 코드 모양)인지 판단하게 하고, 그렇다면 검사로 바꿀 수 있게 실수를 구체적으로 쓰고, 아니면 NONE이라 답하게 한다. NONE이면 후보를 만들지 않고, 실패한 초안처럼 대기(backoff)한다.
- 반증 단계는 지적들이 그 실수를 보여 주지 않거나 검사로 구분할 수 없으면 반증한다.
