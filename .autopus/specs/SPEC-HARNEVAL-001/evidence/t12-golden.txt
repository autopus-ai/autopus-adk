## Codex shell environment policy (REQ-HE-08 "credential only in the codex process") -> PASS on the sandbox path
probe: `codex sandbox -P bench -C <ws> <pilot profile_args> [policy] -- /usr/bin/env` with canaries
HARNEVAL_AGENT_CREDENTIAL, CODEX_HOME, OPENAI_API_KEY and PLAIN_CANARY in codex's own environment.
  default policy (no override)            commands see all 4 canary keys and values (OPENAI_API_KEY included: no
                                          default *KEY* exclusion in this version)
  inherit="none" + set={allowlist}        commands see exactly the set keys + CODEX_SANDBOX, CODEX_SANDBOX_NETWORK_DISABLED
  inherit="all" + include_only=[allowlist] commands see exactly the allowlist keys + the two CODEX_SANDBOX keys; PATH
                                          keeps codex's own arg0 helper prefix (the only CODEX_HOME-derived value)
golden_trial.agent_argv uses inherit="all" + include_only=AGENT_KEYS, so codex keeps its PATH handling and no
credential key reaches a command.
`codex exec --strict-config -c shell_environment_policy.inherit_typo="all"` -> exit 1 "unknown configuration field
`shell_environment_policy.inherit_typo` in -c/--config override" before any session; without --strict-config the same
typo is accepted silently. With the valid golden overrides --strict-config proceeds to session creation (stopped by
the outer no-network sandbox), so every override the runner passes is known to codex-cli 0.160.0.
not-run: the command environment inside a real `codex exec` turn (needs a model turn; the maintainer's first live
session checks it, e.g. a canary in --credential-env and `env` in the transcript).
